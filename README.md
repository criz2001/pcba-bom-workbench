# PCBA BOM 工作台 · 项目说明

> 本地运行的 PCBA BOM 核对与生成工具：把 **Altium 原理图 / PCB 设计文件**、**待核对 BOM**、**ERP 物料总表**、**企业 BOM 模板** 放在一起，自动完成「三方交叉核对」和「从设计文件生成 BOM」两件事。
> 全程离线、数据不出本机，无需安装数据库或服务端组件。

| 项目 | 值 |
| --- | --- |
| 应用名称 | PCBA BOM 工作台（PCBA-BOM-Workbench） |
| 版本 / 构建 | v2.7.0 · build 20261027（[更新日志](CHANGELOG.md)） |
| 运行平台 | Windows 10 / 11（桌面窗口模式依赖 WebView2） |
| 技术栈 | Python 3.10+ / Flask / openpyxl / olefile / pywebview + 原生 HTML/CSS/JS |
| 数据存储 | 本地文件（工作区目录 + JSON 状态 + 任务快照） |
| 网络行为 | 仅监听 `127.0.0.1`，不上传任何文件 |

---

## 一、它解决什么问题

手工核对 BOM 时最常见的四类错误，正是本工具的核心检查目标：

1. **封装写错** —— BOM 规格里写 `0603`，PCB 实际封装却是 `0805`；
2. **位号漏写或多写** —— BOM 少了 `C12`，或者写了设计文件里根本不存在的 `J5`；
3. **用量与位号数不符** —— 用量填 2，位置号却只列了 1 个；
4. **物料编码错误** —— 编码为空、编码在总表里查不到、名称与总表不一致。

工具以 **PCB 与原理图** 作为位号/封装的「实物基准」，以 **物料总表** 作为编码基准，对 BOM 逐行核对，并输出带高亮和说明的 Excel；同时支持反向流程：直接从设计文件提取元件、匹配物料编码、套用企业模板生成一份新 BOM。

## 二、功能总览

### 1. BOM 三方交叉核对

- 输入 4 类：原理图（`.SchDoc`）、PCB（`.PcbDoc`）、待核对 BOM（`.xlsx/.xlsm/.csv`）、物料总表（可选）。
- 先校验 PCB 与原理图的位号集合是否一致（判断版次是否对齐），再执行 10 类规则核对。
- 结果输出 4 个工作表的 Excel：原表高亮 + 问题清单 + 位号对照 + 值比对。
- 规则可逐项开关，输出内容可勾选。

### 2. BOM 生成

- 从原理图 + PCB 提取位号、规格、实际封装，按位号关联合并。
- 按「规格值 + 封装」在物料总表中匹配编码，给出 **确定 / 候选 / 待确认** 三种状态。
- 支持两套合并方式：按「规格 + 封装 + 编码」合并为一行，或每个位号一行。
- 套用企业 BOM 模板输出（列结构、字段名、格式、固定值沿用模板），未匹配项仍保留在 BOM 中并标注。

### 3. 物料库与模板

- 物料总表：搜索（编码/名称/规格）、按「有效/禁用」筛选、分页浏览、统计。
- BOM 模板：上传、预览列结构、设为默认、删除。

### 4. 桌面窗口

- 双击 `start.bat` 打开独立窗口（pywebview + WebView2），不依赖浏览器；
- 无 pywebview 或 WebView2 时自动退化为「起服务 + 打开默认浏览器」，功能不受影响；
- 桌面模式额外提供原生「另存为」对话框、打开输出目录等能力。

## 三、快速开始

### 方式一：安装到本机，生成桌面图标（推荐）

1. 确认已安装 **Python 3.10 或更高版本**，安装时勾选 *Add Python to PATH*。
2. 双击根目录下的 `安装.bat`（内部调用 `install.ps1`）。
3. 安装器会自动：
   - 检查 Python 3.10+（不满足会直接报错，不再“装完才发现用不了”）；
   - 把程序复制到 `%LOCALAPPDATA%\Programs\PCBA-BOM-Workbench`；
   - 数据目录设为 `%LOCALAPPDATA%\PCBA-BOM-Workbench\data`（与旧版一致，升级不丢数据）；
   - **创建 `.venv` 并安装依赖**（首次约 1–3 分钟；失败会明确报错并提示检查网络）；

## 四、支持的输入文件

| 类型 | 允许的扩展名 | 解析方式与要点 |
| --- | --- | --- |
| 原理图 | `.SchDoc`、`.SchDot` | 读取 OLE 复合文档的 `FileHeader` 流，提取位号、Value、Comment、PCB 模型封装、引脚数 |
| PCB | `.PcbDoc` | 读取 `Components6/Data`（或 `Components/Data`），以 `SOURCEDESIGNATOR` 为位号、`PATTERN` 为实际封装 |
| 待核对 BOM | `.xlsx`、`.xlsm`、`.csv` | 自动定位表头行并映射列：项次、子项物料编码、子项物料名称、子项规格型号、用量、位置号、备注 |
| 物料总表 | `.xlsx`、`.xlsm`、`.csv` | 自动映射：物料编码、物料名称、规格型号、数据状态、禁用状态、物料属性、基本单位、库存位置 |
| BOM 模板 | `.xlsx`、`.xlsm` | 识别表头行与列名，映射到 13 类标准字段，另记录冻结窗格/筛选等元信息 |

限制与提示：

- 旧版 `.xls` **不支持**，会明确提示「请另存为 .xlsx 后重试」；
- 单次上传上限 256 MB；
- 表格最多读取 200000 行；
- 表头识别会扫描前 12 行，匹配不到列名时使用内置兜底列号（BOM：E/F/G/J/M；物料总表：B/C/D/F/G/H/I）；
- CSV 自动尝试 `utf-8-sig` / `gbk` / `utf-8` / `latin-1` 编码。

## 五、BOM 校对（核对）

### 5.1 页面流程

| 路由 | 页面 | 作用 |
| --- | --- | --- |
| `/` | 工作台 | 两个功能入口、运行指标、最近任务、上次核对问题分布 |
| `/check/setup` | 文件与规则 | 上传 4 类输入、开关 10 类规则与输出选项、实时校验基准一致性 |
| `/check/running` | 核对进行中 | 整体进度、6 步流程状态、解析日志（可暂停）、实时统计 |
| `/check/result` | 核对结果 | 概览指标、问题分布、问题清单（级别筛选 + 搜索）、位号缺失、值比对、导出 |
| `/check/detail` | 问题详情 | 从结果页进入的行级详情抽屉 |
| `/gen/setup` | 文件与模板 | 上传设计文件与素材、查看提取预览、选择合并方式、模板列映射 |
| `/gen/result` | 生成结果 | 指标、BOM 预览、待确认项、输出前校验、导出 |
| `/library` | 物料库与模板 | 物料总表浏览检索、模板管理 |

### 5.2 处理步骤

任务按固定 6 步推进，界面上逐步显示状态与说明：

1. **读取文件** —— 载入 4 类输入并记录任务文件清单；
2. **解析原理图** —— 提取元件、位号、Value/Comment、模型封装；
3. **解析 PCB** —— 提取元件、`PATTERN`、层与无位号元件；
4. **校验基准** —— 比较 PCB 与原理图位号集合，不一致时提示「版次可能未对齐」；
5. **逐条核对 BOM** —— 执行启用的规则，实时推送问题日志；
6. **生成结果** —— 写出 4 个 Sheet 的 Excel 并保存任务快照。

### 5.3 十类核对规则

| # | 键 | 规则 | 默认级别 | 判定依据 |
| --- | --- | --- | --- | --- |
| 1 | `footprint` | 封装不符 | 严重 | BOM 名称/规格中的封装代号 ≠ PCB 实际 `PATTERN`（若编码对应封装与 BOM 一致、仅 PCB 不同，则降为「一般」并提示确认版次） |
| 2 | `name` | 名称与总表不符 | 严重 | BOM 子项物料名称 ≠ 物料总表同编码名称 |
| 3 | `missing` | 位号缺失 | 严重 | `PCB ∪ 原理图位号 − BOM 位号` 不为空 |
| 4 | `unknown` | 位号不存在 | 严重 | `BOM 位号 −（PCB ∪ 原理图）` 不为空（多余位号或拼写错误） |
| 5 | `duplicate` | 位号重复 | 严重 | 同一位号出现在多行 BOM，或同一行的位置号列里重复书写（基于 `ref_occurrences()` 的出现次数判定，集合版 `all_refs()` 无法发现） |
| 6 | `qty` | 用量≠位号数 | 严重 | 用量分子 ≠ 位置号拆分后的位号个数 |
| 7 | `nocode` | 缺物料编码 | 严重 | 子项物料编码为空（有总表时会附推荐编码） |
| 8 | `badcode` | 编码不存在 | 严重 | 编码在物料总表中查不到 |
| 9 | `format` | 位号格式 | 一般 | 全角逗号、分号、顿号、连续逗号、多余空格 |
| 10 | `item` | 项次跳号或缺项次 | 一般 | 项次不连续，或有项次/用量却无编码、名称、位号（残缺空行） |

规则之外还有几条「兜底判定」，不计入 10 类，但对结果有实际影响：

- **物料已禁用**：命中的编码在总表中标记为禁用 → 提示级别；
- **位号取自备注**：位置号列为空、备注里写了位号时，用设计文件位号集合过滤后回填，避免整片误报「位号缺失」；
- **值比对（需确认）**：BOM 声明阻容值与原理图标注值不同，只作提示，不判严重（原理图与 BOM 常非同一版次）；
- **PCB 无位号元件**：单独列出，不会静默丢弃。

若未上传物料总表，则「编码不存在」「名称与总表不符」两类自动跳过，界面会明确提示剩余 8 类照常执行。

### 5.4 输出选项与结果工作簿

可在「文件与规则」页勾选：

| 选项 | 默认 | 产物 |
| --- | --- | --- |
| `highlight` | 开 | 原 BOM 表：问题单元格按级别着色（严重红 / 一般黄 / 提示蓝），末尾新增「核对结果（自动核对）」列逐行说明 |
| `problemSheet` | 开 | 「问题清单」Sheet：序号 / 级别 / 类型 / BOM 行号 / 涉及列 / 问题描述 / 处理建议，冻结首行 |
| `refSheet` | 开 | 「位号对照」Sheet：位号 × PCB 封装 × 原理图标注值 × 是否在 BOM × 核对结论 |
| `valueSheet` | 开 | 「值比对(需确认)」Sheet：BOM 声明值 vs 原理图标注值 |
| `verifyBaseline` | 开 | 是否在核对前先校验 PCB 与原理图基准一致性 |

输出文件命名：`<BOM 文件名>-BOM核对结果.xlsx`，实际落盘为 `outputs\<时间戳>_<名称>`，**不会修改上传的原文件**。

## 六、BOM 生成

### 6.1 取值优先级

| 字段 | 优先级（从高到低） |
| --- | --- |
| 规格值 | 原理图 `Value` ＞ 原理图 `Comment` ＞ 器件描述 / 库引用 |
| 封装 | PCB 实际 `PATTERN` ＞ 原理图 PCB 模型 ＞ 由库引用/规格推断 |

当 `Value` 与 `Comment` 都存在且不相同时，采用 `Value`，并把冲突记录到 BOM 备注和生成结果的「待确认项」中。

### 6.2 合并方式

| 模式 | 说明 | 行数 |
| --- | --- | --- |
| `merge`（默认） | 按「归一化规格值 + 封装 + 编码」合并为一行，汇总数量与位号 | ≤ 元件数 |
| `perRef` | 每个位号单独一行（逐位号明细） | = 元件数 |

约束：数量必须等于该行唯一位号数；合并前去重位号并按「字母前缀 + 数字」自然排序；规格相同但封装不同的器件不合并。

### 6.3 物料匹配状态

对每个元件在物料总表中匹配编码，结果分三档：

- **确定** —— 规格值与封装唯一匹配（含「规格值就是物料编码」的直接命中）；
- **候选** —— 规格值匹配，但存在多个同规格同封装物料，或封装只有一侧可识别、无法自动比对；
- **待确认** —— 匹配不到，或元件本身没有可用规格值。

关键设计取舍：**规格值无法判定时一律不给候选**，绝不「只按封装匹配」——否则任意 0603 元件都会被塞上总表里编码最小的一条物料，错误看起来还挺合理。

### 6.4 未匹配项如何处理

未匹配的元件 **仍然保留在 BOM 中**，不会消失：

- 编码列留空（避免被 ERP 误导入）；
- 名称回退链：总表名称 → 设计规格 → 库引用 → 描述 → 位号，保证不留空；
- 行底色标黄 + 编码单元格批注 + 备注列写「★待确认：未匹配到物料编码，需人工指定」；
- 生成结果页可导出「待确认清单」CSV，或复制全部物料编码。

### 6.5 模板机制

- 模板只决定 **列结构、字段名称、格式与固定值**；不沿用模板中的物料内容、位号、数量、BOM 版本与父项信息（写入前会清空示例数据行）。
- 字段映射覆盖 13 类：项次、子项物料编码、子项物料名称、子项规格型号、子项单位、用量分子/分母、位置号、备注、父项物料编码、BOM 版本、BOM 简称、数据状态。
- 没有模板时使用 **内置 9 列模板**：项次 / 子项物料编码 / 子项物料名称 / 子项规格型号 / 子项单位 / 用量:分子 / 用量:分母 / 位置号 / 备注。
- 模板损坏、加密、是改了扩展名的 `.xls`、合并单元格冲突等情况 **不会让生成失败**：自动降级为内置模板，并在日志中说明原因。

输出文件命名：`<原理图文件名>-BOM-<时间戳>.xlsx`。

## 七、物料库与模板

- **物料总表**：显示总条数、有效/禁用数量；支持按编码/名称/规格关键字搜索，按「全部 / 有效 / 禁用」筛选，分页浏览（每页 5–200 条）。
- **禁用物料**：总表中「禁用状态」为 `是/Y/YES/TRUE/1/已禁用/停用` 的条目视为禁用，不参与候选匹配，命中时在核对结果中提示。
- **模板管理**：上传后自动识别列结构与元信息；可设为默认模板、删除；生成时默认使用默认模板。

## 八、工作区与数据目录

### 8.1 工作区位置解析优先级

1. 环境变量 `BOM_WORKSPACE`；
2. 项目目录下 `config.json` 的 `workspace` 字段（安装程序写入，指向用户数据目录）；
3. 项目目录下的 `workspace`（开发态默认）。

安装版 `config.json` 的内容形如（本机路径因机器而异）：

```json
{
  "workspace": "C:\\Users\\<你的用户名>\\AppData\\Local\\PCBA-BOM-Workbench\\data",
  "version": "2.7.0",
  "installedAt": "2026-09-22 16:03:05"
}
```

> `config.json` **不纳入版本库**（安装程序生成、含本机绝对路径）；克隆本仓库后可直接用 `config.example.json` 复制一份改名，或不提供该文件——此时自动使用项目内的 `workspace` 目录。

### 8.2 工作区目录结构

```text
<workspace>/
├─ uploads/         上传的原始文件（文件名带 12 位随机前缀，避免重名）
├─ outputs/         核对结果与生成的 BOM
```

## 十、技术实现要点

### 10.1 Altium 文件解析

- 二进制 `.SchDoc` / `.PcbDoc` 是 **OLE 复合文档**（魔数 `D0CF11E0A1B11AE1`），用 `olefile` 读取关键流：
  - 原理图：`FileHeader`；
  - PCB：`Components6/Data`（兼容旧版 `Components/Data`）；`Pads6/Data` 是纯二进制记录，不解析，引脚数改用原理图引脚记录统计。
- 流内容是「`uint32 小端长度` + 正文（含结尾 NUL）」的连续记录帧，正文以 `|` 开头；长度异常时向前重新同步，尽量不因单条坏记录丢掉整份文件。
- 记录字段键统一转 **小写** 后取值：真实文件用 PascalCase（`LibReference`），自行拼的样例是全大写（`LIBREFERENCE`），统一下来两种都能取。
- 子记录通过 `OWNERINDEX` 挂到父元件上，注意 **`OWNERINDEX + 1` 偏移**；类型不符时回退原值兼容个别导出方式。
- 用到的记录类型：`1` 元件、`2` 引脚、`34` 位号、`41` 参数（Value/Comment）、`44/45` PCB 模型。
- 文本编码优先 UTF-8，出现无效字节时改用 GBK（中文 Windows 的 PcbDoc 描述字段常见）。
- 同时兼容以 ASCII 文本保存的 Altium 文件。

### 10.2 规格与封装的归一化

- 阻容值：`104` / `0.1uF` / `100nF` 归一为同一值；`5K1` → `5.1K`；纯数字在电阻语境补 `R`。
- 带测试条件的写法（`600R@100MHz`）与 `600R` 视为等价；但 **不会抹掉单位后比较**（否则 1K 与 1M 会相等）。
- 封装代号：先识别贴片代号（0201/0402/0603/0805/1206/…），再识别封装类型关键字（SSOP、QFN、SOT-23、SMA…）。
- 在物料名称里查找规格值时做 **字符边界校验**，避免 `2K` 命中 `22K`、`20K` 命中 `120K`。
- 位号拆分支持半角/全角逗号、分号、顿号与空白；从备注列提取位号时只认「1~4 个字母 + 1~4 位数字（可带尾字母）」形态，并用设计文件位号集合二次过滤。

### 10.3 容错与降级策略

| 场景 | 行为 |
| --- | --- |
| 未安装 pywebview / WebView2 不可用 | 自动退化为「起服务 + 打开默认浏览器」 |
| 桌面窗口启动异常 | 关闭服务、清理就绪标记，再走浏览器回退 |
| 环境安装失败（网络问题） | `start.bat` 退回系统 Python 启动 |
| 重复双击 | 单实例文件锁拦截，并把已有窗口切到前台 |
| 模板不可用 | 改用内置 9 列模板，日志说明原因 |
| 未提供物料总表 | 生成照常输出，全部标「待确认」；核对跳过 2 类编码规则 |
| 单个元件匹配出错 | 只把该元件标为「待确认」，不影响整份 BOM |
| 原理图/PCB 解析不到元件 | 明确告警说明会退化成什么结果，而不是笼统报「无法生成」 |

## 十二、后台任务模型

核对与生成都在后台线程执行，前端通过轮询任务接口获取进度：

- **状态**：`running` / `done` / `failed` / `cancelled`；
- **步骤**：核对 6 步（读取文件 → 解析原理图 → 解析 PCB → 校验基准 → 逐条核对 → 生成结果）；生成 6 步（读取文件 → 解析原理图 → 解析 PCB → 合并元件 → 匹配物料总表 → 写入 BOM）；
- **日志**：内存保留最近 400 条，接口返回最近 200 条；级别含 `INFO` / `OK` / `WARN` / `ERROR`；
- **持久化**：每个任务写入 `tasks/<taskId>.json`，重启后仍可查看上次核对/生成结果；
- **取消**：取消请求在步骤边界检查；已完成步骤不回滚，但不会再进入下一步，任务状态记为 `cancelled`。

## 十三、桌面模式与原生能力

`app/desktop.py` 的启动链路：

```text
起本地 HTTP 服务（127.0.0.1，优先 8760，占用则顺延，最多再让系统分配）
        ↓
pywebview 打开原生窗口（Windows 使用 WebView2 后端）
        ↓
窗口关闭 → 服务停止 → 进程退出
```

细节：

- 窗口默认 1460×920，最小 1080×680，允许选中/复制表格文本；
- 单实例：工作区 `instance.lock` 文件锁，重复启动会尝试把已有窗口切到前台；
- 图标：通过 `WM_SETICON` 设置窗口/任务栏图标（pywebview 本身不提供 Windows 图标设置）；
- 就绪标记：窗口真正显示后才写 `logs/desktop.ready`，`start.bat` 依赖它判断启动成功；
- WebView2 缓存写入 `logs/webview`，并保留 localStorage（主题偏好跨次生效）。

暴露给前端的原生接口（`window.pywebview.api`，浏览器模式下不存在，前端自动回退为普通下载）：

| 方法 | 作用 |
| --- | --- |
| `app_info()` | 返回模式、标题、工作区与输出目录 |
| `save_task_output(task_id)` | 把任务结果另存为（原生保存对话框），随后在资源管理器中选中文件 |
| `save_text(filename, content)` | 保存前端生成的文本（如待确认清单 CSV），UTF-8 BOM 编码 |
| `open_folder(kind)` | 打开 outputs / uploads / workspace 目录 |

- 双击 `卸载.bat`，或执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File uninstall.ps1
```

- 默认行为：关闭正在运行的实例 → 删除桌面/开始菜单快捷方式 → 移除「已安装的应用」注册表项 → 删除程序目录 → **保留数据目录**。

- 追加参数：
  - `-RemoveData`：连同工作区（上传文件、输出结果、物料库）一起删除；
  - `-Quiet`：减少输出。
- 未指定参数时会交互询问是否同时删除数据。

## 十六、常见问题

| 现象 | 排查方向 |
| --- | --- |
| 双击后没有窗口 | 看 `logs/desktop.log`；`start.bat` 等待约 60 秒仍无 `logs/desktop.ready` 会弹窗提示 |
| 桌面图标没了 / 换电脑想重建 | 重新运行 `安装.bat`，会覆盖安装并重建桌面和开始菜单图标，数据不会丢 |
| **安装成功，但双击桌面图标提示启动失败** | 旧版安装器只复制文件，首次启动才装依赖；依赖安装失败时会出现这个现象。请重新运行 `安装.bat`（2.7.0+ 会在安装阶段准备好运行环境），仍失败则把 `logs\start.log` 与 `logs\desktop.log` 发给维护人 |
| 双击桌面图标没反应 | 看安装目录下 `logs\start.log` 与 `logs\desktop.log`；也可手动运行安装目录的 `start.bat` 查看控制台输出 |
| 提示「已经在运行」 | 已有实例持有工作区文件锁，从任务栏切到已打开窗口即可 |
| 首次启动很慢 | 正在创建 `.venv` 并安装依赖，属正常；之后启动是秒级 |
| 依赖安装失败 | 检查网络/代理；重新运行 `安装.bat`，安装器会重建 `.venv`。若系统 Python 已有 Flask/openpyxl/olefile，也可继续兜底启动 |
| 上传文件提示「解析失败」 | 上传只做解析，错误原因会显示在文件槽与接口返回中：可能是文件加密、扩展名与内容不符、表格为空、不是有效的 Altium 文件 |
| `.xls` 提示不支持 | 用 Excel 另存为 `.xlsx` 后重新上传 |
| 核对结果「封装不符」很多 | 先确认 PCB 与原理图是否同一版次；基准不一致时页面会告警。BOM 与编码都对、仅 PCB 不同时该问题会降为「一般」 |
| 生成结果大量「待确认」 | 多半是未上传物料总表，或原理图元件缺少 Value/Comment（没有可比对的规格值），工具不会强行匹配 |
| 表格列识别错位 | 确认表头包含中文列名（项次/子项物料编码/位置号等）；实在特殊可改用兜底列序（BOM：E/F/G/J/M） |
| 浏览器能开但按钮点不动 | 该按钮是桌面模式专属（另存为、打开输出目录），浏览器模式请用普通下载 |
| 工作区想换位置 | 设置环境变量 `BOM_WORKSPACE`，或修改 `config.json` 的 `workspace` |

## 十七、二次开发提示

- **后端入口**：`app/server.py` 的 `create_app()`；业务编排在 `app/flows.py`；纯逻辑都在 `app/core/`，可脱离 Flask 单独调用与测试。
- **新增核对规则**：在 `app/core/checker.py` 的 `RULES` 增加条目并实现判定，同时补 `ADVICE` 文案、`app/static/assets/pages/check_setup.js` 的 `RULES`（页面开关），必要时补 `app/core/report.py` 的 `KIND_COLS`（高亮列）。
- **前端结构**：页面是 Jinja2 模板（`app/templates/`），共享外壳 `base.html`；脚本加载顺序 `api.js`（请求/提示/toast/overlay）→ `app.js`（状态与轮询）→ `slot-meta.js`（文件槽元数据）→ `pages/*.js`（单页逻辑）。
- **样式**：`app/static/assets/pages/*.css` 由设计稿通过 `tools/extract_css.py` 抽取，不建议手工微调；要改视觉请改设计稿后重跑脚本。
- **新增文件类型或字段**：上传类型与扩展名在 `app/server.py` 的 `ALLOWED_EXT`；解析摘要逻辑在 `app/core/store.py` 的 `_parse()`；前端文件槽在 `slot-meta.js`。
- **版本号**：`app/__init__.py` 的 `__version__` 与 `BUILD`，会显示在标题栏与状态栏；发版时同步更新 `CHANGELOG.md` 并打 tag。
